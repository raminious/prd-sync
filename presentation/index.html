PRD Admin

One place for PRDs. Each change has a version. People and coding agents read the same text.

Author: Ramin Mousavi - raminmousavi.dev

Main idea: a repo records the PRD version that its code agrees with. The diff to the latest version is the work list.

Speaker notes · 15 sThis is a prototype. It has one job: it keeps our PRDs and our code in agreement. I will show the idea in four slides, and then the app.

Use ← → or Space to move between slides.

02

Two problems today

The PRD and the code do not agree

  • The repo keeps a hand copy of each PRD for the coding agents
  • The PRD changes, but the copy does not
  • The agents build from the old copy

A change does not reach the team

  • A PRD changes after the work started
  • The developers and the design team do not always get the news

Result: people and agents can build from an old PRD.

Speaker notes · 40 sIn the compute console repo, the agents read a hand copy of the S3 PRD. Our own skill file says that this copy is a snapshot and not the source of truth. So each PRD change needs a person who updates the copy. The second problem is about people. When a PRD changes, the news depends on memory. If someone forgets, the developers and the designers continue with the old text.
03

One source for each PRD

  • PRDs are Markdown, in one place
  • People read them in the browser. Coding agents read them through an API
  • A save does not change a version. It adds a new one
  • Each version has an author and a mandatory change summary
  • Each save sends a Slack message with the summary and a link to the diff

Nobody must remember to tell the team. The save tells them.

Speaker notes · 40 sThe tool works like git, but for PRDs. You cannot change an old version. You can only add a new one. So we always know who changed what, and when. The change summary is mandatory. It goes to Slack with a link to the diff. There is one exception: the writer can mark a save as a minor edit, for example a spelling correction. Then no message goes out.
04

The version pin

Each repo records the PRD version that its code agrees with. This record is the pin.

"Does the code agree with the PRD?" now has an exact answer.

Speaker notes · 50 sThis idea connects the PRD to the code. The PRD has versions 1, 2, and 3. The repo says: my code agrees with version 1. The tool then gives the diff from version 1 to the latest version. That diff is the list of work that is not done. When the work is done, the pin moves to version 3. The pin is in git with the code. So each commit tells us which PRD version it agrees with.
05

Coding agents follow the same rule

A repo copies one skill file. The file holds the pins and these steps:

  1. Before the work, get the diff from the pin
  2. If the PRD changed, tell the developer what changed
  3. Read the latest PRD, then do the work
  4. Move the pin only when the code agrees with each change
Speaker notes · 40 sThe agents do not read a copy. They ask the tool each time. On the right is real output from the prototype: version 2, the date, the author, and the summary. The full diff comes below that. I tested the skill file with a new agent in a test repo. It reported the PRD change before it wrote code. It did not move the pin, because the change was not built.

07

State and next step

Works today

  • PRDs with versions and a diff page
  • A Slack message on each save
  • An API for coding agents
  • A skill file that a repo can copy

Not in the prototype

  • Real login and roles
  • A server. It runs on one laptop
  • The connection to hcd-web
  • Email messages

Open question

  • Where do we write PRDs today?
  • Will we write them only here?

Proposal: a pilot with one PRD and one repo. S3 Console Integration in hcd-web.

Speaker notes · 40 sThe prototype shows the idea. It is not ready for the team: it has one shared password, and it runs on my machine. The largest risk is not technical. The tool helps only if we write PRDs here and in no other place. So I propose a small pilot with one PRD and one repo. After the pilot, we know if the pin works for us.
